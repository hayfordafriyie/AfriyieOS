1. What the fixtures are, and why these ones
===============================================================================

Every .xz stream is produced by the REFERENCE implementation (liblzma via
Python's lzma module) and compared byte for byte against the payload it was
built from. Streams are classified by walking their LZMA2 chunk control
bytes, so the ones this build claims to decode and the ones it must refuse
are separated by the format's own structure rather than by a hand list.

3. The payoff: a .deb the way current dpkg-deb writes one
===============================================================================

control.tar.zst and data.tar.zst — what a current Debian or Ubuntu package
uses. The reader picks its decompressor from the member's MAGIC BYTES, not
from the file extension, so gzip and Zstandard both work and the reader no
longer cares what the name claims.
