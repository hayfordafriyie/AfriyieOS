## Summary

The first milestone. AfriyieOS stopped being a document and became code that runs
on bare metal: firmware loads the boot bridge, the bridge describes the machine,
the kernel takes over, initialises the CPU, brings up a framebuffer and draws a
real interface to it — and the whole path is asserted automatically.

## The nine bugs that stood between "it compiles" and "it boots"

None of these were visible by reading. They are recorded in full in
[../debug-log.md](../debug-log.md).

| # | Bug | How it presented |
| --- | --- | --- |
| 1 | `EFI_SYSTEM_TABLE` packed with wrong offsets | Would have triple-faulted on the first console write; caught by static asserts |
| 2 | `kernel_entry` not at the image start | Black screen after `ExitBootServices` — the CPU ran an arbitrary C function |
| 3 | FAT32 root cluster had no FAT entry | mtools: "Fat problem while decoding 2 0"; Linux vfat: "can't read superblock" |
| 4 | Console output between `GetMemoryMap` and `ExitBootServices` | `ExitBootServices` rejected the map key, four times, then fatal |
| 5 | Boot pointer delivered in the wrong register | Kernel logged "boot_info invalid"; the 0x7000 backup saved the boot |
| 6 | One index for two buffers in `efi_console_print` | Garbled text: "AryeS010(ed EIbo rde" |
| 7 | GCC flags passed to NASM | `nasm: fatal: unrecognised output format 'freestanding'` |
| 8 | Quotes inside `-I"path"` and `-Wl,-T,"path"` | Linker told to open a filename beginning with a double quote |
| 9 | Literal path instead of `@AF_KERNEL_BIN@` | `incbin: unable to get length of file 'kernel.bin'` |

The lesson worth keeping: **bugs 2, 3, 4 and 5 all produced a silent hang or a
wrong-but-plausible result, not an error message.** They were found by asserting
invariants (`kernel_entry == 0x100000`), by reading the image with someone else's
FAT driver, and by fixing the ordering rather than retrying the call. Retrying
would have hidden bug 4 forever.

## What works

### Boot

- **UEFI boot bridge** (`boot/uefi/`) loaded by firmware from
  `EFI/BOOT/BOOTX64.EFI`
  - complete UEFI 2.10 type definitions, every structure in specification order
    with **natural alignment** and a static assert on the size and on the offset
    of every member that is called
  - `EFI_BOOT_SERVICES` lists all 45 members including the unused ones, because
    omitting any of them shifts every later offset
  - entry point declared `__attribute__((ms_abi))`; the jump to the kernel
    declared `sysv_abi` so the handoff pointer lands in the register the kernel
    entry stub reads
  - watchdog disabled; GOP framebuffer recorded including the stride
  - memory reserved at `0x100000` with `AllocateAddress` so firmware fails loudly
    rather than relocating the kernel
  - UEFI memory map normalised into `af_memory_region_t`; framebuffer regions
    overridden so the PMM can never allocate video memory
  - `ExitBootServices` fetched-and-called back to back, with a retry loop that
    refetches the map and stays silent in between
  - kernel embedded with `incbin`, removing the file-system code path and
    structurally guaranteeing bridge and kernel come from the same commit

- **Kernel entry** (`kernel/arch/x86_64/entry.asm`) — in a dedicated `.text.boot`
  section so it is the first bytes of the image, installs its own stack, clears
  `.bss`, and calls `kmain`

- **CPU initialisation** — 64-bit GDT with the final selector numbering, a
  256-entry IDT with 48 NASM-generated stubs, and the 8259 PICs remapped from
  `0x08` to `0x20`

### Display

- **Framebuffer** — surface init with format and pitch validation; packed-RGB to
  native pixel conversion for `RGBX8888`, `BGRX8888` and `RGB565`. Confirmed on
  screen: GOP reported `RGBX8888` and the splash came out in the intended colours
- **Primitives** — clipped pixel, rectangle, outline, lines, vertical gradient,
  alpha blending, rounded rectangles, drop shadow
- **Text** — complete 8×16 printable-ASCII bitmap font, scalable and measurable
- **Splash screen** — responsive: a centred card in landscape, a stacked layout in
  portrait. The first version of the breakpoint rule the Shell adopts at v0.8

### Diagnostics

- **Serial console** — COM1 115200 8N1 with a scratch-register probe
- **Structured logging** — elapsed-time prefix, level filter, module tag,
  swappable sink, bounded `vsnprintf`
- **On-screen console** — the boot log mirrored to the screen
- **Panic path** — interrupts off first, recursion guard, reason/file/line/function,
  full register dump including `CR2` for page faults. Never reboots

## Known limitations

- **Single core only.** SMP arrives in v1.2.
- **The kernel is identity-mapped at 1 MiB, not in the higher half.** A
  higher-half image faults on its first instruction fetch without paging, so the
  move is coupled to the v0.2 work.
- **The portrait splash layout is not verified on screen.** The desktop layout is
  asserted by a screenshot test; the phone branch is exercised in code and by the
  breakpoint expression, but OVMF's default GOP mode is landscape and changing it
  needs a firmware setting rather than a QEMU flag. Deferred to v0.6, where the
  compositor gives us resolution control.
- **Interrupts are masked after the PIC remap.** v0.1 installs no IRQ handlers,
  and an unhandled IRQ is worse than a masked one.
- **Only 16- and 32-bit linear framebuffers.** A BLT-only GOP mode is reported
  clearly and the kernel continues with serial output.
- **The boot bridge embeds the kernel with `incbin`,** so a kernel change rebuilds
  the boot application. Loading the kernel from the ESP begins in v0.2.
- **`#DF` has no dedicated IST stack** — that needs the TSS, which v0.4 writes.

## Boot markers

CI asserts these appear, in this order, on the serial console:

```
AF_GDT_READY      GDT loaded, segment registers reloaded
AF_IDT_READY      IDT installed, PIC remapped
AF_FB_READY       framebuffer initialised and the splash drawn
AF_TEST_OK        in-kernel self tests all passed
AF_BOOT_OK        kmain reached the idle loop; the kernel is alive
```

Any of these is a hard failure: `AF_PANIC:<reason>`, `AF_TEST_FAIL:<name>`.

## In-kernel self tests

71 checks, run on bare metal at every debug boot, reporting over serial:

- **Memory and strings** — `memset` including unaligned destinations (the
  word-at-a-time fast path can only start once the pointer is 8-byte aligned),
  `memcpy`, `memmove` in both overlap directions, `strlcpy`/`strlcat` truncation
  with a guard byte past the end
- **Number formatting** — `INT64_MIN`, `UINT64_MAX`, hex with and without a
  prefix, zero padding, human-readable byte sizes
- **`vsnprintf`** — `%s %c %d %i %u %x %X %p`, width, left and zero padding,
  string precision, literal `%%`, and truncation that still NUL-terminates
- **Boot handoff validation** — every rejection path exercised for real with a
  hand-built structure: wrong magic, wrong version, too-small size, empty memory
  map, too many regions, unaligned region, zero-length region, no usable memory,
  and a framebuffer whose pitch is smaller than `width × bpp / 8`
- **Framebuffer** — invariants, and out-of-bounds drawing that must be clipped
  rather than corrupt memory

### Boot

- **UEFI boot bridge** (`boot/uefi/`) — loaded by firmware from
  `EFI/BOOT/BOOTX64.EFI` on the EFI System Partition
  - disables the firmware watchdog so a slow boot is not reset underneath itself
  - locates the Graphics Output Protocol and records the linear framebuffer,
    including the **stride**, which is the single most common cause of a skewed
    first image
  - reserves physical memory at `0x100000` with `AllocateAddress`, so firmware
    fails loudly rather than relocating the kernel to somewhere it was not linked
  - normalises the UEFI memory map into `af_memory_region_t`
  - marks any region covering the framebuffer as `AF_MEM_FRAMEBUFFER`, so the
    PMM can never allocate video memory
  - calls `ExitBootServices` in a retry loop with a refetched `MapKey`
  - jumps to the kernel with paging off and interrupts disabled

- **Kernel entry** (`kernel/arch/x86_64/entry.asm`) — installs its own stack,
  zeroes `.bss`, and calls `kmain`

- **CPU initialisation** — a 64-bit GDT with the final selector numbering
  (`0x08`, `0x10`, `0x18`, `0x20`, `0x28`) and a 256-entry IDT with 48 real
  stubs. The 8259 PICs are remapped from `0x08` to `0x20`; without that, the
  first timer tick arrives as a double fault.

### Display

- **Framebuffer** — surface initialisation with format and pitch validation,
  and packed-RGB conversion to native pixels for `RGBX8888`, `BGRX8888` and
  `RGB565`
- **Drawing primitives** — clipped pixel, rectangle, outline, horizontal and
  vertical line, vertical gradient, alpha blending, rounded rectangles and a
  drop shadow
- **Text** — a complete 8×16 printable-ASCII bitmap font with scaling, and
  measurement for centring
- **Splash screen** — a responsive boot screen: a centred card in landscape
  (desktop) and a stacked layout in portrait (phone). This is the first version
  of the breakpoint rule the Shell uses from v0.8.

### Diagnostics

- **Serial console** — COM1 at 115200 8N1, with a scratch-register probe so a
  machine without a UART cannot hang the kernel waiting on a transmitter that
  never drains
- **Structured logging** — elapsed-time prefix, level filter, module tag,
  timestamped, with a swappable output sink
- **On-screen console** — the boot log is mirrored to the screen, so a developer
  without a serial cable can still see it
- **Panic path** — interrupts off first, recursion guard, then reason, file,
  line, function, build identity and a full register dump including `CR2` for a
  page fault and eight raw stack words. It never reboots: the fault state is the
  entire value of the crash.

### Tooling

- **`tools/build_toolchain.sh`** — builds `x86_64-elf` and `aarch64-elf` GCC
  cross-compilers. Idempotent, so a partial run resumes.
- **`tools/mkimage.py`** — builds a bootable GPT disk image with a FAT32 ESP in
  pure Python: boot sector, FSInfo, FAT, long-name entries, multi-cluster files,
  directory growth, primary and backup GPTs with correct CRCs.
- **`tools/verify_image.py`** — independent structural verifier, 35 checks.
- **`tools/run_qemu.py`** — interactive boot, and a `--test` mode that asserts
  the kernel's boot markers for CI.

## Bugs found and fixed during development

Recorded in full in [../debug-log.md](../debug-log.md). The ones worth noting
because they are the classic first-boot traps:

1. `mov rsp, kernel_stack_top` would load the **contents** of that `.bss`
   address — which is zero — instead of its address. Fixed with
   `lea rsp, [rel kernel_stack_top]`.
2. The UEFI pixel-format mapping was inverted. UEFI names formats by **byte order
   in memory**; `af_pixel_format_t` names the **little-endian integer layout**.
   The original mapping would have swapped red and blue on every desktop.
3. The FAT32 directory writer stopped collecting free slots at the `0x00`
   terminator, so a three-entry long-name chain landing in a directory's last
   free slot could not be written. Found by writing 200 files into one directory.
4. A 32 MiB ESP cannot be FAT32 at any cluster size. The builder now refuses it
   with an explanation rather than emitting a file system firmware would decline
   to mount.
5. `.gitignore` matched a bare `core`, which swallowed the entire `kernel/core`
   source directory.
